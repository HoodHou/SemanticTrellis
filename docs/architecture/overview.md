# Architecture overview

## Goal

SemanticTrellis turns repository understanding into a maintained, reviewable
asset. It separates facts extracted from source code from meaning curated by an
agent or a human reviewer.

## Layered model

```text
Repository bytes
      |
      v
Structural facts          Disposable, reproducible
      |
      v
Change set and impact     Incremental, repository-local
      |
      v
Curator proposals         Reviewable patch operations
      |
      v
Curated semantic graph    Canonical, stable, versioned
```

### Structural facts

Structural facts describe files, symbols, imports, calls, and declarations.
They are generated by parser adapters and can always be rebuilt.

The structural index stores one disposable contribution per supported source
file. A contribution contains symbols, unresolved references, non-fatal parser
diagnostics, the source hash, and the exact extractor identity. TypeScript and
JavaScript use the TypeScript Compiler API adapter. C# uses the ast-grep Node API
with its prebuilt Tree-sitter C# grammar. Python uses the same runtime with a
prebuilt Tree-sitter Python grammar and represents dynamically ambiguous calls
as conservative `invoke` references. Lua uses a prebuilt Tree-sitter Lua grammar
and models module tables, callbacks, `require` imports, and dynamic invocation in
the same contribution format. Other languages plug into the same registry.

### Artifact projections

Repository inventory also classifies every Git-visible regular file outside the
eligible-text policy. Unsupported bytes are never decoded or disclosed by the
projection inventory. A format-aware Agent host can instead propose a strict,
deterministic `.strellis.json` or `.strellis.md` sidecar whose metadata binds the
original repository-relative path and SHA-256.

Projection validation is read-only. Registration requires the unchanged
document and a token bound to the source hash, normalized projection digest,
exact target path, and existing target digest. The original artifact is never
modified. A disposable projection index reuses stat-stable hashes and marks only
the projection for a changed source stale.

### Change set and impact

The maintenance engine compares the current repository inventory with the last
local snapshot. It emits added, changed, and removed files and maps those files
to curated nodes through source provenance.

Symbol-level maintenance removes a changed file's previous contribution and
inserts the new one while replaying unchanged contributions. A persisted
target-name reverse index identifies unchanged files whose references may be
affected by changed definitions. Resolution-relevant symbol identities are
compared before propagation, so implementation-only edits stay within their
owning file. Only changed and affected files are re-resolved; an unchanged
refresh skips edge resolution and index persistence entirely.

Read queries use the cached in-process index, probe Git deltas or source stats,
and repair stale contributions once before retrying. Source reads are verified
and cached by content hash, with byte-order-mark-aware decoding. Natural-language
`ask` retrieval combines ranked symbols and bounded verified source bodies in
one call. This keeps MCP and CLI behavior consistent while preserving exact
stale-source detection.

### Curator proposals

An AI curator never writes the graph directly. It emits a patch containing
typed operations. Patch validation checks stable identity, locked nodes,
referential integrity, and source provenance before persistence. Invalid or
non-relative provenance is an error and blocks the patch. A source path missing
from the current snapshot is a warning returned for review and does not block
the write by itself.

### Curated semantic graph

The curated graph represents systems, subsystems, components, concepts,
invariants, files, and external dependencies. It is deliberately smaller and
more stable than the symbol graph.

## Application lifecycle

### Bootstrap

1. Preview the complete Git-visible disclosure set without returning source.
2. List unsupported artifacts and their current projection state without
   disclosing binary content.
3. Optionally validate and register approved format-aware projections.
4. Obtain explicit user approval for Agent source review.
5. Freeze and hash the complete eligible-text repository snapshot.
6. Split every eligible text file and registered projection into stable source chunks.
7. Let the connected Agent summarize every chunk with resumable checkpoints.
8. Roll chunk summaries and structural evidence into one semantic summary per
   file.
9. Page the complete summary corpus to the Curator Agent.
10. Review and apply its sourced graph proposal as an explicit patch.
11. Mark the session complete only at 100% coverage, clean projection status,
    and a clean graph audit.

### Sync

1. Probe repository state.
2. Compute the delta against the local snapshot.
3. Find curated nodes whose provenance intersects the delta.
4. Create or update review items.
5. Update disposable structural state.
6. Leave the approved graph unchanged until a patch is reviewed.

### Audit

Audit validates graph integrity, missing source provenance, stale source paths,
and unclassified repository files. A full AI reclassification is not part of a
normal audit.

## Module boundaries

```text
CLI adapter
    |
Application use cases
    |----------------------|
Domain rules        Infrastructure adapters
    |                       |
Provider ports       File system and JSON storage
```

The domain layer is platform independent. AI providers, parser runtimes,
databases, and MCP are adapters at the boundary.

## Agent boundary

MCP is the primary machine-facing adapter. A server instance is bound to one
repository root at process start, so tool arguments cannot redirect it to a
different workspace. Read tools return structured content and human-readable
text; write tools declare their effects through MCP annotations.

Canonical graph changes use two calls. `validate_patch` applies a proposal only
in memory and returns a token derived from the current graph, exact patch, and
the current review-queue entries selected by `mark-reviewed`. `apply_patch`
recomputes that token immediately before writing and rejects stale or changed
input, while unrelated review items do not invalidate the token. Host approval
remains necessary because MCP annotations are hints rather than an authorization
mechanism.

Locked curated nodes add another invariant: modification and removal are denied
unless the exact patch operation explicitly carries `overrideLocked: true`.
